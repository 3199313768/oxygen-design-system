# Oxygen 完整组件文档站设计

日期：2026-10-30。状态：用户已确认并完成本地实施与验收；公网部署尚未执行。

## 目标与已确认方向

基于现有 Storybook 建设可公开访问的中文组件文档站。每个公开组件族覆盖组件介绍、设计规范、API 参数、基础示例、不同状态、交互示例、使用限制、可访问性说明，并提供实时调整 Props、查看效果、复制相应代码的 Playground。

GitHub 源码仓库可以继续私有。文档站构建产物及其包含的组件实现和示例会对访问者可见，不能把公开部署描述为保护前端实现的手段。

## 当前依据与工作区边界

- `apps/storybook/.storybook/main.ts` 已启用 addon-docs、addon-a11y 和 autodocs，目前只收集 Story 文件。
- `preview.tsx` 有统一 DocsPage，但其内容只有标题、简介、主示例、Controls 和其他示例，尚未覆盖八项完整内容。
- 现有展示多数按多个组件合并分组，固定 render 不适合作为逐组件参数 Playground。
- 工作区已有主题、ConfigProvider、浮层及消费页面修改；Themes Story 已配置主题 Controls。保留并兼容这些修改，不把它们当作本任务新增成果。
- `packages/ui/src/index.ts` 与 `packages/patterns/src/index.ts` 是公开组件范围依据；源码类型、实际默认值、行为和现有测试是 API 与说明依据。
- 当前 CI 构建 Storybook，但没有发布文档站的流程。

## 方案比较

| 方案 | 收益 | 成本与限制 |
| --- | --- | --- |
| Storybook Docs + Controls，推荐 | 复用主题、示例、构建和检查能力，组件文档与演示在同一入口维护 | 需要逐组件建立参数、说明和示例 |
| 独立文档网站，嵌入 Storybook | 页面组织和品牌展示更自由 | 维护两套路由、构建和内容关联，当前没有必要 |
| Storybook 加在线代码沙箱 | 可自由编辑 JSX 和多文件代码 | 增加依赖、运行环境和异常处理；超出已要求的 Props 调试范围 |

采用第一种方案。当前 Playground 是 Props 调试器，支持参数、预览和代码联动；不增加任意代码执行环境。

## 信息架构和覆盖范围

入口提供开始使用、设计基础、主题与配置、组件和页面模式。开始使用包括安装、样式导入、受控与非受控说明、组合式组件用法和构建静态站的方法。

每个公开组件族提供独立入口。复合组件的子组件 API 必须在所属入口中列出，不能只写根组件参数。图标作为独立总览，说明公开导出、尺寸、装饰与交互语义。

| 分类 | 组件族 |
| --- | --- |
| 通用与配置 | Button、ConfigProvider、Typography、Icons |
| 布局 | Layout、Space、SpaceCompact、Divider |
| 导航 | Breadcrumb、Tabs、DropdownMenu、NavigationMenu、Pagination |
| 表单与录入 | Field、Label、Form、FormItem、Input、Textarea、InputNumber、Select、Combobox、Cascader、Checkbox、RadioGroup、Switch、Slider、ColorPicker、TagInput、Transfer、Upload |
| 日期时间 | Calendar、DatePicker、DateRangePicker、TimePicker |
| 数据展示 | Card、Badge、Table、Descriptions、Statistic、Steps、Timeline、Tree、TreeSelect、Image、ImagePreview、Tag |
| 反馈与浮层 | Alert、Toast、Message、Notification、Dialog、AlertDialog、Popover、Sheet、Tooltip、Skeleton、Spin、Progress、Result、Accordion、Collapsible |
| 其他 | QRCode |
| 页面模式 | AppShell、EmptyState、PageHeader、StatusMessage |

FormItem、SpaceCompact 可以在父组件文档下拥有明确小节及直接定位入口，避免与根组件表混淆。现有状态组合及视觉回归 Story 继续保留，归入综合示例，不以它们代替独立组件文档。

## 每组件的八项内容

| 内容 | 交付要求 |
| --- | --- |
| 组件介绍 | 明确用途、适用场景、与相邻组件的选择关系 |
| 设计规范 | 说明层级、尺寸、内容、布局及语义 Token，引用现有基础规范；不虚构尚未实现的能力 |
| API 参数 | 列出名称、类型、必填、默认值和含义；覆盖自定义参数、事件、公开数据类型、复合子组件，以及继承的原生/Radix 属性说明 |
| 基础示例 | 可运行、可复制的最小例子，包含所需导入和完整组合结构 |
| 不同状态 | 根据能力覆盖默认、禁用、加载、错误、空、只读等；不适用状态说明原因，不新增无效 Props |
| 交互示例 | 输入与反馈、受控更新、展开关闭、选择、分页等真实交互；静态组件展示组合或布局调整并解释其静态职责 |
| 使用限制 | 明确请求、鉴权、业务校验、时区、数据规模、宿主职责及已知边界中适用的部分 |
| 可访问性 | 说明命名、标签、键盘、焦点、状态播报、装饰图标和消费方责任；不能将自动检查通过等同读屏验收 |

说明须针对具体组件编写，不能通过同一段通用文本填满所有页面。API 自动提取结果仅作依据和辅助，必须核对默认值、继承关系、泛型及组合式组件。

## Playground 行为

- 为每个组件族选择有意义且能演示效果的参数，显式配置 component、args 和 argTypes；示例渲染必须消费这些 args。
- 枚举用选择框，布尔值用开关，数字提供有效边界，文本和结构化数据采用适合的编辑方式。不可直接编辑函数、ref、复杂 ReactNode 时说明限制，并提供完整示例。
- 受控示例正确维护交互状态，外部 Controls 修改与组件内部操作均能产生可解释的结果；不得把受控值锁死。
- 显示与当前参数及示例结构一致的可复制代码。代码包含必要导入、Provider、子组件、状态和回调，不能只输出一个无法运行的根标签。
- 提供恢复默认参数能力。复制成功、剪贴板不可用或拒绝时均有可理解反馈，失败时允许手动选择代码。
- 保留现有浅色、深色、跟随系统工具栏，以及局部主题和 Portal 行为。
- 不执行用户输入的任意 JavaScript，不引入在线编译或第三方沙箱服务。

- `apps/storybook/.storybook/main.ts`：按实际方案增加文档资源收集和排序，保留现有插件。
- `apps/storybook/.storybook/preview.tsx`：将完整文档模板接入现有预览，保留当前主题修改。

- `apps/storybook/stories/`：增加逐组件文档及参数示例；文档元数据、API 说明与复杂交互示例按职责拆文件，避免所有组件塞入一个渲染函数。
- `docs/` 和 `README.md`：说明文档维护、公开发布目标及实际验收情况，与已有基础规范交叉链接。
- `tests/`、`scripts/`、`package.json` 和现有 CI：增加文档完整性检查和必要浏览器验收入口，维持现有检查。
- 优先复用已经安装的 Storybook 能力；新增依赖必须解释必要性。不修改公开组件 API，不为文档示例新增业务组件。

## 公网交付边界

本任务先交付可构建、可本地预览和可托管的静态文档站，以及发布操作说明。静态资源路径须支持直接访问文档链接，不能依赖开发服务器。

用户尚未指定托管平台、账户、域名或访问策略。不得猜测生产域名或修改外部账户；具体自动部署配置在平台确定后接入，实际发布需单独明确。可公开部署不等于已经上线。

## 验证与完成标准

1. 公开组件清单与文档逐项对应；检查八项章节、API、示例引用和有效链接。检查内容实际有意义，不以标题存在当作完整验收。
2. 核对所有组件族及其公开子组件的 API：类型、必填、默认值、事件和继承属性说明与源码一致。
3. 每个 Playground 在真实浏览器中至少修改一项参数，观察预览更新；对生成代码核对相应参数及完整结构。复制后读取剪贴板，覆盖拒绝或不可用回退。
4. 验证典型复杂组件的输入、受控更新、选择、打开关闭、焦点返回、加载/错误/空状态及恢复默认值。
5. 桌面及 390px 窄屏检查目录、参数表、代码、预览和主题；所有组件页面检查渲染错误和资源加载失败。长表格、代码采用局部滚动，页面不出现意外横向溢出。
6. 运行现有 TypeScript、ESLint、相关单测、组件库构建与 Storybook 静态构建；从静态产物启动服务复查页面和直接链接。
7. 记录验证范围、未覆盖的真实设备或读屏器场景。公网可访问性只有在实际部署后验证，不能根据静态构建成功推断。
8. 最后检查本任务 diff，保留工作区原有修改，不自动提交、推送或发布。
