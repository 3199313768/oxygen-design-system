# Foundation v1 收尾设计

用户已批准推进上一轮明确列出的未完成项。此次以可验证的本地交付和远端只读证据为目标，不提交、推送、发布、改变仓库可见性或擅自选择许可证。保留并行的组件文档工作。

## 构建与交付

在现有真实 tarball 消费验证中增加最小单组件构建、模块/导出证据及 raw/gzip JS/CSS 预算。先测生产基线，再将允许增长上限固定到受版本管理的配置；执行时不能自动抬高预算。CSS 仍为整包入口，不宣称逐组件剔除。新增门禁纳入 check 与发布候选验证。

远端核查优先复用已登录的 GitHub CLI，支持现有环境变量身份，不输出凭据。检查 main 的经典保护、有效 Ruleset、所需工作流与运行结果。发布核查只读 npm registry 与身份，明确 Trusted Publishing 不能由本地 token 缺失推断。对需要远端变更的差异准备精确配置和应用前后检查，保留用户控制。

## 字体与动效

字体默认继续继承宿主，新增可覆盖的正文、系统、等宽字体角色；不加载外部字体。保留字号、行高和尺寸。动效统一为交互、退出、面板、旋转、脉冲时长及标准/进入/退出/线性/脉冲缓动，沿用现有节奏和 motion-fast/base 兼容入口。减少动态效果按组件关闭非必要动画与过渡，并保留进度、loading、展开及焦点功能。

## ColorPicker 与验收

采用原生 button 触发器和真实文本输入各司其职的方案，保留 button ref/id、确认才提交、取消、受控与非受控行为。必填/值错误语义放在真实输入上；关闭的触发器通过可访问描述表达状态并保留 Field 关联。移除整文件 ARIA lint 豁免，不使用不匹配行为的角色掩盖错误。

用行为回归和真实浏览器核查字体继承与覆盖、动效与 reduced-motion、ColorPicker 名称/描述/状态/键盘焦点。整理组件适用状态矩阵，区分自动行为证据、截图复核和未完成的人工/实体设备验收。未执行的人工读屏、实体设备及远端发布明确保留为外部验收项。

## 许可证

首次讨论时用户表示不确定。后续只读核查发现远端 main 与 npm 两个 0.1.1 包已经采用 MIT；用户随后明确选择“沿用已发布的 MIT”。因此将仓库及两个包的 LICENSE、manifest 与 tarball 校验统一对齐现有发布基线，不另选或改变许可证。
