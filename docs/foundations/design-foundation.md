# Design Foundation · 设计基础规范

制定日期：2026-10-30。品牌定位与 Dark 主题契约已由用户确认；尺寸、圆角、排版等沿用现有基线。本文与 [Engineering Foundation](engineering-foundation.md) 共同约束设计与开发。

“已确认”表示产品与设计决策已确定；“已实现”必须有源码依据；“已验收”必须说明实际验证范围。Dark 已有实现并完成本地消费回归；其验收范围见 [主题实施验收](../reviews/2026-10-30-dark-theme.md)。

## 1. Oxygen 品牌视觉定位

> Oxygen 是一套清晰、克制、可靠的企业级工作台设计系统，面向复杂信息与高频操作，让用户准确理解、顺畅完成工作。

优先服务数据管理、业务运营、配置管理和专业工具类桌面工作台。桌面效率是主要设计场景，窄屏与触屏保持关键内容可读、操作可达。组件 API 与文案保持业务中立，让不同产品通过内容与组合形成自己的流程。

体验优先级：**信息清晰 → 操作可靠 → 工作效率 → 品牌表达**。用户价值面向实际工作者，复用价值面向 React 开发者与设计协作者。

| 视觉性格 | 设计判断 | 落实方式 |
|---|---|---|
| 清晰 | 用户能辨认当前信息、状态和下一步动作 | 稳定的文字层级、操作层级、可理解的反馈和错误说明 |
| 沉静 | 长时间工作时视觉负担可控 | 中性背景、适量品牌色、克制的阴影与动效 |
| 精确 | 同类信息与交互遵循一致规律 | 统一基线、图标、尺寸、对齐、数值排版和状态表达 |
| 有呼吸感 | 密集信息仍能辨认分组与重点 | 在信息组、主要内容和操作之间安排留白，保持组内紧凑 |

蓝色用于主要行动、选择和焦点识别；状态色保持各自语义。信息层级优先通过排版与间距表达，再按必要性增加边框、底色或阴影。每增加一层容器都应解释其分组、交互或层级用途。

本定位不替代标志、品牌资产或市场传播规范；这些资产未在此次讨论中定稿。借鉴既有设计系统的通用原则不构成 API 兼容或逐像素复刻承诺。

## 2. 色彩系统与语义 Token

当前颜色使用 OKLCH 表达，由 [tokens.css](../../packages/ui/src/styles/tokens.css) 提供。具体数值以源码为准；新增及调整应同步组件、状态和主题验收。

| 语义 | 现有 Token 分组 | 使用原则 |
|---|---|---|
| 页面与容器 | `background`、`surface`、`surface-subtle`、`surface-popup` | 表达承载层级，区分页面、内容与轻量区域 |
| 文字 | `text`、`text-muted`、`text-placeholder`、`text-disabled` | 正文、辅助、占位、不可用状态分别处理；占位不能替代标签 |
| 边界与填充 | `border`、`border-subtle`、`border-strong`、`fill-hover`、`fill-disabled` | 边界按重要性分层，悬停与禁用使用各自角色 |
| 品牌与选择 | `primary`、`primary-hover`、`primary-foreground`、`primary-subtle`、`primary-border` | 表达主要操作、选中及相关底色与边框，避免所有内容都用主色 |
| 功能状态 | `success`、`warning`、`error` 及各自的 `subtle`、`border`、`text` | 按前景、文字、底色、边框分别配对；状态同时通过文字或图标表达 |
| 焦点 | `focus` | 为键盘用户提供可辨认的焦点，不用单纯 hover 替代 |

前缀统一为 `--oxygen-color-`。主题切换应保持语义名称与用途稳定，通过映射改变颜色；不让业务组件自行拼接浅色/深色硬编码。信息提示可使用品牌相关角色，不能在未实现时宣称已有独立 info 色阶。

深色主题须分别校准品牌蓝和功能色，检查文字/底色、图标/底色、边界/背景及焦点/相邻状态的关系。不能通过整体反色生成深色主题，也不能假定所有主色背景都适合相同的前景色。

## 3. 字体、字号、字重

组件默认继承宿主字体，不自动下载字体。正文覆盖角色为 `--oxygen-font-family-body`，未设置时使用 `inherit` fallback；不能在根处用 CSS-wide `inherit` 假装固定字体值。`--oxygen-font-family-system` 为 `system-ui, -apple-system, BlinkMacSystemFont, "Segoe UI", sans-serif`，`--oxygen-font-family-mono` 为 `ui-monospace, SFMono-Regular, Menlo, monospace`。宿主可全局或局部覆盖，代码文本保持独立 mono 角色。Storybook 的 Inter 优先展示栈不表示库自动加载 Inter。

| 用途 | 字号 / 行高 | 使用说明 |
|---|---|---|
| 注释、补充信息 | 12 / 18px | 次级信息，关键操作或错误说明不只依赖小字 |
| 标签 | 14 / 20px | 控件标签，通常使用 500 字重 |
| 正文 | 14 / 22px | 页面内容、说明及多数数据 |
| 分组标题 | 16 / 24px | 组内标题 |
| 区块标题 | 18 / 26px | 页面区块标题 |
| 标题补充层级 | 20 / 28px | 对应现有 Typography 的三级标题 |
| 页面标题 | 24 / 32px | 工作页面的主要标题 |
| 展示标题 | 28 / 36px | 需要更强层级的标题场景 |

现有 Typography H1–H5 为 28/36、24/32、20/28、16/24、14/22。HTML 标题级别表达文档结构，视觉字号按上下文选择；不可仅为字号改变标题语义或重复页面级标题。

字重基线为 400（正文）、500（标签与适度强调）、600（标题与重要强调）。金额等可比较数值按列对齐；长标题、长字段与中英文混排应验证换行和截断，关键数据应保留完整信息的访问方式。

## 4. 间距与尺寸体系

默认间距尺度为 4、8、12、16、24、32px，对应 `space-1/2/3/4/6/8`。同组内容保持紧凑，不同任务组通过更大的间距分隔；优先复用相近尺度，特殊值需要有明确的布局或交互原因。

| 项目 | 默认基线 |
|---|---|
| 默认控件高度 | 36px |
| 小尺寸控件高度 | 32px |
| compact 模式默认控件高度 | 32px |
| 触屏点击目标 | 至少 44px，视觉控件可更小，但有效区域不得重叠 |
| 常用图标 | 16px |
| 标签到控件间距 | 6px |
| 控件到帮助信息间距 | 4px |
| 默认字段组间距 | 24px |
| compact 字段组间距 | 16px |

默认模式用于日常工作；compact 用于高密度场景，不能缩小触屏可达区域。当前 compact 会将 `space-4` 从 16 调整为 12px、`space-6` 从 24 调整为 16px，因此这些 Token 在密度上下文中不是固定像素常量。

窄屏通过重排、换行和局部滚动适配，保持标签、状态和主要操作可达。尺寸沿用现有 API，不因主题切换新增或改变尺寸枚举。

## 5. 圆角、边框、阴影

- 控件圆角为 6px，容器圆角为 8px。圆形头像、单选、徽标等有语义形态的元素按各自用途处理。
- 边框采用 subtle、默认、strong 层级。常规容器边界克制，选中、错误和焦点保持明确区分；当前部分边框宽度仍在组件 CSS 中定义，未形成完整宽度 Token。
- 阴影沿用 `shadow-surface`、`shadow-popup`、`shadow-modal`。平面内容主要依靠分组与边界；下拉和弹窗用阴影辅助表达悬浮。
- 现有关键层级 Token 为 dropdown 30、popup 50、modal 70；新浮层应验证与宿主、嵌套浮层和模态遮罩的关系，不随意使用更大的 z-index 解决问题。
- 深色环境通过明度层级与边界共同表达容器关系，阴影作为辅助；边框和阴影参数已写入深色 Token，调整后按真实场景回归。

## 6. Light / Dark 主题

### 6.1 已确认的视觉契约

Light 与 Dark 是同一产品的两套明度环境，保持布局、尺寸、排版、密度、信息层级及操作方式一致。

Dark 使用带轻微冷色倾向的中性深灰：页面背景最深，内容容器略亮，弹窗与浮层进一步突出。正文采用柔和浅色，辅助文字保持可读；品牌与状态颜色单独校准。

hover、selected、focus、disabled、loading、invalid 和 readonly 等适用状态必须保持可辨认。主题切换不改变内容、表单值、选择状态、展开状态或当前焦点，不重置正在进行的操作。

图片与视频保留自身内容，不做全局反色。业务图表提供适合深色背景的配色规则，数据与状态含义保持不变；主题切换不能篡改业务数据颜色所表达的含义。

### 6.2 已确认的产品行为与职责

| 事项 | 契约 |
|---|---|
| 可选模式 | 浅色、深色、跟随系统 |
| 默认行为 | 未指定时保持浅色，兼容现有应用；宿主显式选择跟随系统后才响应系统偏好 |
| 显式选择 | 浅色或深色选择不因系统变化被覆盖；跟随系统时响应系统主题变化 |
| 用户偏好 | 宿主应用负责选择入口、保存、恢复及账户同步策略；组件库不自行写入用户存储 |
| 首次加载与 SSR | 宿主负责在首次渲染前确定偏好与初始主题，库应提供可同步应用的接入方式，避免主题错误闪现与 hydration 不一致 |
| 范围 | 支持全局主题与局部区域主题；局部显式选择优先于外层，未指定的后代继承所属区域 |
| 浮层 | 下拉、Tooltip、Popover、Dialog 等跟随所属触发区域；Portal 到其他 DOM 位置仍保持这一语义 |
| 宿主隔离 | 局部主题不修改整个宿主页面的主题；多个实例可以分别呈现 |

### 6.3 实现边界与验收

当前源码提供浅色与深色 Token、`ConfigProvider.theme` 和 `OxygenTheme` 类型，通过 `data-oxygen-theme` 建立作用域，并保留 density/locale 接口。未指定 theme 时继承最近的 React 模式或宿主 CSS 边界，宿主也未配置时保持浅色。

深色 Token 数值、原生 `color-scheme` 和 Portal 来源模式传递已实现，浅色数值和已有公共 API 保持兼容。接入、首次渲染和局部 Token 自定义限制见 [主题接入](../themes.md)；具体数值以源码为准，后续调整仍需真实场景验收。

验收至少包括：表格、筛选表单、编辑弹窗、导航、状态反馈；覆盖全局与局部主题、嵌套区域、所有适用交互状态、系统变化、首次加载及主题切换时的状态保留。检查真实页面的文字可读性、键盘焦点、浮层与容器边界；实体设备和人工读屏验收单独记录。

## 7. 组件尺寸与状态规范

尺寸使用第 4 节基线。状态按组件适用性验收，不要求所有组件机械拥有同一组 props。

| 组件类别 | 必查状态与行为 |
|---|---|
| 按钮与操作 | default、hover、active、focus、disabled、loading；主次层级、图标名称、重复触发 |
| 输入与选择 | 空值、有值、hover、focus、invalid、disabled、readonly（适用时）；必填、帮助、清空 |
| 复选、单选、开关 | 选中与未选、混选（适用时）、焦点、禁用、标签点击与键盘 |
| 表格与列表 | 空、加载、失败、选中、悬停；长内容、排序/分页（适用时）与窄容器 |
| 弹窗与浮层 | 打开、关闭、取消、长内容、嵌套；焦点进入、约束、返回及 Escape 行为 |
| 上传与异步反馈 | 等待、进行中、成功、失败、取消；进度、重试入口（适用时）与卸载清理 |

加载保留正在执行的行动语义，禁用表达当前不可操作；两者不能仅靠同样的灰化表达。选中与悬停不同，错误与焦点可同时存在。失败信息说明问题，并在可恢复时提供下一步；权限策略由宿主决定。

状态矩阵是设计与交付要求，不表示所有历史组件及组合已经完整验收。现有检查记录见 [全组件设计检查](../reviews/2026-10-29-design-system.md)。

## 8. 交互、动效与无障碍规范

- 操作结果必须可理解；表单校验关联到实际控件，帮助与错误可访问，不能仅用颜色表示必填或失败。
- 优先使用原生语义，复用 Radix 已有能力；每个可交互控件提供可访问名称与可见焦点。键盘操作符合控件类型，避免额外制造不必要的 Tab 停靠点。
- 模态内容管理焦点进入、约束与关闭后返回；触发器消失时提供合理的后备焦点。Escape、取消、关闭与保存的语义明确。
- 保持目前 `motion-fast = 120ms`、`motion-base = 150ms` 基线。动效解释展开、切换、加载与反馈，不妨碍连续操作；响应减少动态效果偏好。
- 语义时长为 `motion-duration-interaction`（fallback 旧 base）、`exit`（fallback 旧 fast）、`panel=180ms`、`spin=750ms`、`pulse=1200ms`；均带 `--oxygen-` 前缀。交互/退出角色在使用处解析 fallback，保留局部旧 Token 覆盖能力。缓动角色 `motion-easing-standard/enter/exit/linear/pulse` 分别为 ease/ease-out/ease-in/linear/ease-in-out。只对具名属性做 transition，禁止 transition: all。减少动态效果逐组件关闭非必要旋转、脉冲、展开和进度过渡，状态内容与数值保持可读。
- 触屏目标遵循至少 44px 的已选基线，避免扩展点击区互相覆盖。缩放、长文案、窄屏和键盘操作都纳入验收。
- 自动可访问性扫描、对比度检查和行为测试应结合人工复核；自动扫描通过不能代替人工读屏、真实设备或完整可访问性认证。

ColorPicker 的整文件 ARIA 规则例外已移除：原生 button 保持触发/ref/标签关联，通过描述表达关闭状态；必填与值错误语义由真实文本编辑控件表达，外部错误与草稿错误合并。自动测试不替代实际读屏播报；组件适用状态与具体人工任务见 [状态矩阵](component-state-matrix.md)和[人工验收清单](manual-accessibility-checklist.md)。
